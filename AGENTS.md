# AGENTS.md

Инструкции для AI-агентов, работающих с этим репозиторием. Зеркало — [CLAUDE.md](CLAUDE.md) (для Claude Code); при изменении одного обновляй второй. Подробный разбор кода — в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Что это

CLI-чат с локальной LLM через LM Studio (OpenAI-совместимый API, по умолчанию `http://localhost:1234/v1`) с персистентной памятью, RAG и автосжатием контекста. Три модуля:

- `chat.py` — точка входа, REPL, команды, выбор модели, стриминг, триггер сжатия;
- `memory.py` — класс `Session` (история, системный промпт, саммари), сохранение в `data/sessions/*.json`, функция `compress`;
- `rag.py` — `RagIndex`: чанкинг (structured по статьям + скользящее окно), извлечение текста из PDF, эмбеддинги через LM Studio, косинусный поиск, индекс в `data/rag_index.json`; плюс слой улучшения ретривала: `rewrite_query` (переписывание запроса по истории), `relevance_filter` (отсев слабых по косинусу, без LLM), `rerank` (LLM-переранжирование + фильтр релевантности); порог `ANSWER_MIN_SCORE` (ниже — детерминированный ответ «не знаю» без вызова модели) и `section_of` для структурированного вывода (ответ + источники + цитаты, собираются из чанков в `main`);
- `user_profile.py` — `Profile`: факты о пользователе с «триггерами», селективная подстановка в системный промпт, `data/profile.json`;
- `gen_params.py` — `GenParams`: пер-модельные параметры генерации (temperature, max_tokens, ...), `data/params.json`.

Зависимости: `openai`, `httpx`, `prompt_toolkit`, `pypdf` (текст из PDF). Папка `data/` — рабочие данные, не код.

## Команды

```powershell
pip install -r requirements.txt   # установка зависимостей
python chat.py                    # запуск чата
python chat.py --model <id> --system "..." --temperature 0.5 --url <url>
```

Автотесты — на `unittest` (без зависимостей), только для RAG, гоняются offline (эмбеддинги подменяются детерминированным фейком в `tests/test_rag.py`):

```powershell
python -m unittest discover -s tests -v                       # весь набор
$env:RAG_TEST_PDF="C:\путь\кодекс.pdf"; python -m unittest discover -s tests   # + проверка на реальном PDF
```

`TestRealPdf` пропускается, если не задан `RAG_TEST_PDF`. Линтера нет. Ручная проверка чата: запустить сервер в LM Studio (Developer → Start Server) и `python chat.py`. Без сервера скрипт печатает подсказку и завершается с кодом 1 — это ожидаемое поведение. Скриптовый прогон (кириллица в пайпе требует UTF-8 без BOM):

```powershell
$OutputEncoding = New-Object System.Text.UTF8Encoding($false); $env:PYTHONIOENCODING='utf-8'
"вопрос`n/stats`n/exit" | python chat.py --model "<id>"
```

## Архитектура

Поток одного сообщения в REPL (`main` в chat.py): RAG-поиск (если включён) → `profile.relevant(вопрос)` → `session.messages += вопрос` → `session.build_messages(rag_context, profile_block)` → `stream_reply` (стриминг + usage) → `session.messages += ответ` → `session.save()` → дебаг-строка (`/debug`) → `maybe_compress` (порог `COMPRESS_THRESHOLD = 0.8` от контекстного окна).

Профиль отбирает факты сравнением эмбеддинга вопроса с «триггерами» факта (примеры вопросов, сгенерированные LLM один раз при `/profile add`). НЕ заменять это на сравнение вопроса с текстом факта или на LLM-отбор перед каждым сообщением — оба подхода испробованы и отвергнуты, причины и цифры в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md#профиль-пользователя-user_profilepy).

LM Studio даёт два API: стандартное `/v1` (chat, embeddings) и расширенное `/api/v0/models` (тип модели, state loaded/not-loaded, размер контекста) — второе используется для выбора модели, поиска эмбеддинг-модели и определения лимита контекста, с фолбэком на `/v1`, если недоступно.

Эмбеддинг-модель грузится лениво (JIT LM Studio) при первом эмбеддинг-запросе. Чтобы RAG/профиль не тормозили на первом сообщении, `warm_up_embeddings` на старте делает пустой эмбеддинг-запрос — но только если эмбеддинги понадобятся (профиль `smart` с фактами или существует `data/rag_index.json`).

Ключевые инварианты (не ломать при изменениях):

- `session.messages` содержит только чистые пары user/assistant. Системный промпт, факты профиля, саммари и RAG-контекст в историю НЕ пишутся — они подклеиваются при каждом запросе в `build_messages` (профиль и саммари — в system-сообщение, RAG — в отправляемую копию последнего вопроса).
- Если `stream_reply` вернул `None`, вопрос откатывается из истории (`messages.pop()`).
- Сжатие (`compress` в memory.py): всё, кроме последних `KEEP_MESSAGES = 10` сообщений, саммаризируется той же моделью; при ошибке — полный откат истории. Старое саммари передаётся в промпт саммаризации, чтобы не терялось. Из ответа reasoning-моделей вырезается блок `<think>`.
- Ctrl+C во время генерации прерывает ответ, но не выходит из чата; частичный ответ сохраняется. Ctrl+C на приглашении «Вы:» — выход.
- Смена модели (`/model`) и системного промпта (`/system`) историю НЕ очищают; `/clear` чистит историю и саммари.
- Сессия автосохраняется после каждого удачного ответа; `Session.id` — это имя файла.
- Параметры генерации: не заданный пользователем параметр НЕ отправляется в запрос — так действует пресет модели в LM Studio; «сброс на дефолт» = удаление переопределения, в коде дефолтов нет. Список параметров — только в `SPEC` (gen_params.py).
- Новая команда чата добавляется в ТРИ места: `HELP_TEXT`, словарь `COMMANDS` (меню подсказок при наборе «/»), ветка `elif` в `main()`. Подсказки работают только при `sys.stdin.isatty()`; при пайпе ввод идёт через `input()` — не ломать этот фолбэк, на нём держатся скриптовые тесты.

## Соглашения

- Весь пользовательский текст (сообщения, справка, README) — на русском.
- API-ключ для LM Studio не нужен; клиенту передаётся заглушка `"lm-studio"`.
- Ввод пользователя очищается от BOM (`﻿`) — он попадает в stdin при пайпе из PowerShell.
- Не добавлять зависимости без необходимости: RAG намеренно на чистом Python (косинус в цикле), без numpy и векторных БД.
- Локальные reasoning-модели (qwen3.5, deepseek-r1) «думают» всегда: reasoning уходит в `reasoning_content`, отключить его через LM Studio нельзя, поэтому служебным LLM-вызовам (саммаризация, генерация триггеров) нужен большой `max_tokens` (тысячи) и вырезание `<think>` из ответа.
