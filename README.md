# localllm — CLI-чат с LM Studio

Терминальный чат с локальной LLM через OpenAI-совместимый API LM Studio: стриминг, персистентная память, RAG по своим файлам и автосжатие контекста.

## Подготовка

1. В LM Studio загрузите модель и запустите сервер: **Developer → Start Server** (по умолчанию `http://localhost:1234`).
2. Для RAG и профиля скачайте в LM Studio эмбеддинг-модель (например, `nomic-embed-text`). Держать её загруженной вручную не нужно: при старте CLI сам подгрузит её (если включён **JIT loading** в настройках сервера LM Studio) — но только когда она понадобится, то есть если у вас есть факты профиля в режиме `smart` или готовый RAG-индекс.
3. Установите зависимости:

```
pip install -r requirements.txt
```

## Запуск

```
python chat.py
```

CLI покажет список чат-моделей (загруженные помечены). Параметры:

```
python chat.py --model <id> --system "Ты — полезный ассистент" --temperature 0.5 --url http://localhost:1234/v1
```

## Команды в чате

Наберите `/` — появится меню со всеми командами и описаниями; оно фильтруется по мере ввода и дополняет подкоманды (`/rag add`, `/profile mode smart`, `/param temperature default`...). Стрелки или Tab — выбор, Enter — подтвердить.

| Команда | Действие |
|---|---|
| `/help` | справка |
| `/model` | сменить модель (история сохраняется) |
| `/system <текст>` | задать системный промпт; без текста — показать текущий |
| `/clear` | очистить историю и саммари текущей сессии |
| `/new` | новая сессия |
| `/sessions` | список сохранённых сессий |
| `/load <номер>` | продолжить сессию из списка |
| `/compress` | сжать историю вручную |
| `/stats` | заполнение контекста, история, профиль, RAG |
| `/profile add <факт>` | добавить факт о себе |
| `/profile` | показать факты; `edit`/`del`/`triggers`/`hint`/`mode` — управление |
| `/param` | показать параметры генерации текущей модели |
| `/legal on` / `/legal off` | юр-режим разом: параметры генерации + ретривал (top_k, дедуп); главный демо-переключатель «до/после» |
| `/param <имя> <значение>` | задать temperature, max_tokens, context_window, top_p, top_k, min_p, penalty, seed |
| `/param preset legal` / `preset off` | применить только параметры генерации юр-агента / снять |
| `/param <имя> default` | вернуть параметру дефолт модели |
| `/param reset` | сбросить все параметры на дефолты модели |
| `/debug` | вкл/выкл строку статистики после ответов |
| `/rag add <путь>` | проиндексировать файл или папку |
| `/rag on` / `/rag off` | включить/выключить RAG |
| `/rag status` | что в индексе |
| `/rag clear` | очистить индекс |
| `/exit`, `/quit` | выход |

Ctrl+C во время генерации прерывает ответ, не закрывая чат.

## Профиль

`/profile add Мне 12 лет` — и модель узнаёт о вас, но только к месту: факт подставляется в системный промпт лишь тогда, когда он относится к вопросу. «Какие фильмы я могу смотреть?» — возраст подставится; «Сколько часов в сутках?» — промпт останется чистым.

Как это работает: при добавлении факта чат-модель один раз придумывает «триггеры» — примеры вопросов, где факт полезен (занимает ~полминуты). Дальше каждый ваш вопрос быстро сравнивается с триггерами через эмбеддинги. `/profile triggers <n>` показывает триггеры факта, `/profile hint <n> <вопрос>` — дописать свой, если автоматика что-то упустила. Режимы: `smart` (по умолчанию), `always` (подставлять все факты), `off`.

## Параметры генерации

`/param temperature 0.3`, `/param max_tokens 2000` и т.д. — настройки хранятся **отдельно для каждой модели** (`data/params.json`) и переживают перезапуск. Не заданный параметр в запрос не отправляется вовсе — тогда действует пресет модели из LM Studio. Поэтому `/param temperature default` или `/param reset` возвращают именно дефолты конкретной модели. Учтите: у reasoning-моделей `max_tokens` включает невидимые размышления — слишком маленький лимит даст пустой ответ.

**Рабочий лимит контекста.** `/param context_window <N>` задаёт лимит контекста, от которого считается порог автосжатия (по умолчанию берётся размер, сообщённый LM Studio при загрузке модели). Сам размер окна модели задаётся в LM Studio при её загрузке; этот параметр лишь управляет тем, при каком заполнении CLI начнёт сворачивать историю, и в запрос к модели **не отправляется**. `/param context_window default` — вернуть размер из LM Studio.

**Юридический режим — два режима, RAG в обоих.** `/legal on` — **все оптимизации**: (1) систем-промпт юр-агента (отвечать фактами и по нормам, ссылаться на статьи, не гарантировать исход дела, не заменять живого юриста, не выдумывать), (2) параметры генерации (пресет `legal`: temperature 0, узкая выборка токенов, штраф за повторы; `max_tokens` намеренно не капается — reasoning-модель иначе обрывается посреди размышлений), (3) ретривал: `top_k=8` + дедуп по статье + rewrite (раскрывает follow-up'ы вроде «раскрой статьи, что ты перечислил») + rerank + grounding-инструкция «отвечай только по фрагментам». `/legal off` — **голый RAG без оптимизаций**: пустой систем-промпт, дефолты модели, `top_k=3`, без дедупа/rewrite/rerank и без grounding-инструкции (модель отвечает по сырым чанкам). Так наглядно сравнивается «до/после» на одном и том же вопросе. Один тумблер, чтобы задать один и тот же вопрос «с оптимизацией» и «без» и сравнить ответы, скорость и расход токенов (см. дебаг-строку).

Если нужно тонко — только параметры генерации: `/param preset legal` / `/param preset off` (то же, что `/param reset`); `/param preset` без аргумента показывает доступные пресеты.

## Дебаг

После каждого ответа печатается строка вида:

```
[18.8 с | промпт 50 + ответ 2024 = 2074 ток. | 107 ток/с | контекст 25% из 8192]
```

— время генерации, размер промпта и ответа в токенах (у reasoning-моделей ответ включает размышления), скорость и заполнение контекстного окна. Отключается командой `/debug`.

## Память

Каждый диалог автоматически сохраняется в `data/sessions/*.json` после каждого ответа. При следующем запуске: `/sessions` — список, `/load <номер>` — продолжить с того же места, вместе с системным промптом и саммари.

## Сжатие контекста

CLI следит за заполнением контекстного окна (размер берёт у LM Studio, расход — из usage API). Когда запрос занимает больше 80% окна, история автоматически сжимается: всё, кроме последних 10 сообщений, превращается в саммари (его пишет та же модель), и диалог продолжается без потери сути. Порог и глубина — константы `COMPRESS_THRESHOLD` в `chat.py` и `KEEP_MESSAGES` в `memory.py`.

## RAG

`/rag add <путь>` индексирует текстовые файлы (txt, md, py, json, ...) и **PDF** (через `pypdf`). Юридические тексты (кодексы) режутся по статьям: заголовок «Статья N.» сохраняется в каждом чанке, длинная статья дробится скользящим окном; обычный текст режется окном по ~800 символов. Дальше эмбеддинги считаются через LM Studio, индекс лежит в `data/rag_index.json`, и перед каждым вопросом ищутся самые близкие чанки. Косинусный поиск — на чистом Python, без внешних векторных БД.

Поверх поиска — переключаемый слой улучшения качества (по умолчанию включён, `/rag rewrite|rerank|filter on|off`):

- **rewrite** — чат-модель переписывает вопрос в самодостаточный запрос по истории (follow-up «а по какому закону?» превращается в полноценный запрос);
- **filter** — дёшево, без LLM, отсекает фрагменты, заметно уступающие лучшему по близости;
- **rerank** — чат-модель переранжирует расширенную выборку и **выкидывает нерелевантное** (может не подставить ничего, если по теме ничего нет).

## Бенчмарк оптимизации

`python bench.py --model <id> --rag` гоняет набор юр-вопросов в двух режимах — базовом и оптимизированном (пресет `legal` + промпт + RAG) — и сводит время, токены, ток/с, а также сохраняет сами ответы для сравнения качества (markdown + JSON в `docs/`). `--isolate` — варьировать только параметры, `--repeat N` — проверка детерминизма. Тем же бенчмарком сравнивают кванты модели (прогнать на разных GGUF). Подробно — в [docs/DAY29-optimization.md](docs/DAY29-optimization.md).

## Веб-сервис (VPS)

Тот же агент, что и в CLI, доступен по HTTP — `web.py` (отдельная точка входа, но
пайплайн переиспользует `rag.py` и юр-режим из `chat.py`, так что локально и на сервере
**одна программа**). На чистом stdlib (`http.server`), без веб-фреймворков.

```powershell
python scripts/build_index.py --url http://127.0.0.1:11434/v1 --embed-model bge-m3  # собрать индекс из corpus/
python web.py --url http://127.0.0.1:11434/v1 --model qwen2.5:1.5b --embed-model bge-m3
```

Работает против любого OpenAI-совместимого API: LM Studio (`/v1`) или **Ollama**
(`http://127.0.0.1:11434/v1`). Эндпоинты: `GET /` — страница чата (`web/index.html`),
`POST /api/chat` — `{answer, sources[], not_known}`, `GET /api/health`.

Развёрнут на VPS: **http://5.129.234.9/**. Деплой — ровно из git (`git ls-files`),
сервер стирается и собирается заново, никаких ручных правок на сервере:

```powershell
git add -A; git commit -m "..."; ./scripts/deploy.ps1
```

Скрипт пакует git-файлы → заливает → пересобирает venv → строит индекс ТК РФ (если нет)
→ ставит systemd (`localllm-web.service`) и nginx из git → рестарт → smoke-тест.
Корпус: `corpus/tk-rf.pdf` (ТК РФ). Индекс (`data/rag_index.json`) — артефакт, в git не хранится.
