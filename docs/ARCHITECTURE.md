# Архитектура localllm

Подробный разбор устройства проекта для разработчиков и AI-агентов. Краткая выжимка — в [CLAUDE.md](../CLAUDE.md) / [AGENTS.md](../AGENTS.md).

## Состав проекта

| Файл | Назначение |
|---|---|
| `chat.py` | Точка входа: аргументы, REPL, команды, выбор модели, стриминг, триггер сжатия |
| `memory.py` | Класс `Session`, сохранение сессий, сжатие истории (`compress`) |
| `rag.py` | `RagIndex`: чанкинг, эмбеддинги, косинусный поиск |
| `user_profile.py` | `Profile`: факты о пользователе, триггеры, селективная подстановка |
| `gen_params.py` | `GenParams`: пер-модельные параметры генерации |
| `data/sessions/*.json` | Сохранённые диалоги (создаются автоматически) |
| `data/rag_index.json` | Векторный индекс RAG |
| `data/profile.json` | Профиль: факты, триггеры и их эмбеддинги |
| `data/params.json` | Переопределения параметров генерации по моделям |
| `requirements.txt` | `openai`, `httpx`, `prompt_toolkit` |

Состояние живёт в JSON-файлах в `data/`; БД и конфигов нет.

## Два API LM Studio

- **`/v1`** (OpenAI-совместимое) — генерация (`chat.completions`, `stream=True`) и эмбеддинги (`embeddings.create`). Ходим через клиент `openai` с переопределённым `base_url`; ключ — заглушка `"lm-studio"`.
- **`/api/v0/models`** (расширенное, `api_v0_models` в chat.py) — тип модели (`llm`/`vlm`/`embeddings`), состояние (`loaded`/`not-loaded`), размер контекста (`loaded_context_length` / `max_context_length`). Используется для: списка чат-моделей с пометкой загруженных, автопоиска эмбеддинг-модели, определения лимита контекста. При недоступности — фолбэк на `/v1/models` (без пометок, лимит `DEFAULT_CONTEXT = 8192`).

`/v1/models` возвращает все *скачанные* модели, не только загруженные: LM Studio с включённым JIT loading сам подгружает модель при первом запросе.

**Прогрев эмбеддинг-модели.** `find_embedding_model` только находит id в списке, но модель остаётся выгруженной, пока не будет первого эмбеддинг-запроса. Чтобы RAG и профиль не тормозили на первом сообщении (и модель не «висела» невыгруженной вопреки ожиданиям), при старте вызывается `warm_up_embeddings` — крошечный эмбеддинг-запрос, который через JIT подгружает модель. Прогрев делается только когда эмбеддинги реально понадобятся: профиль в режиме `smart` с фактами **или** существует файл `data/rag_index.json`. Если JIT в LM Studio выключен, прогрев тихо не удастся и печатается подсказка включить его; функциональность при этом деградирует штатно (профиль → `always`, RAG → сообщение об ошибке).

## Поток одного сообщения

```
ввод пользователя (не команда)
 ├─ RAG включён? → rag_index.search(вопрос) → топ-3 чанка (порог 0.45)
 ├─ profile.relevant(вопрос) → факты с триггером, похожим на вопрос (порог 0.85)
 ├─ session.messages += {"role": "user", ...}
 ├─ session.build_messages(rag_context, profile_block):
 │    [system: системный промпт + факты профиля + саммари] + история,
 │    RAG-контекст подклеивается к копии последнего вопроса
 ├─ stream_reply(): печать чанков + usage (stream_options include_usage)
 ├─ ответ есть → session.messages += assistant; session.save()
 │  ответа нет → session.messages.pop()   # откат вопроса
 ├─ дебаг-строка: время | промпт+ответ ток. | ток/с | % контекста (/debug)
 └─ maybe_compress(): usage.total_tokens > 80% лимита → compress()
```

## Модель состояния: класс Session (memory.py)

Поля: `id` (= имя файла), `created`, `system_prompt`, `model`, `summary`, `messages`.

Инварианты:

1. `messages` — только чистые пары user/assistant. Системный промпт, саммари и RAG-контекст туда **не пишутся** — всё подклеивается в `build_messages` при каждом запросе. Поэтому `/system` можно менять в любой момент, а RAG-мусор не копится в истории.
2. Вопрос без полученного ответа откатывается (`messages.pop()`).
3. Автосохранение после каждого удачного ответа, а также при `/system`, `/model`, `/clear`, сжатии.
4. `/model` и `/system` историю не очищают; `/clear` чистит и `messages`, и `summary`.

## Сжатие контекста

Триггеры: автоматически в `maybe_compress` (chat.py), когда последний запрос занял больше `COMPRESS_THRESHOLD = 0.8` контекстного окна, или вручную `/compress`. Расход токенов берётся из `usage` последнего ответа (LM Studio отдаёт его в финальном чанке при `stream_options={"include_usage": True}`); если usage нет — грубая оценка ~3 символа/токен (`Session.estimate_tokens`).

`compress(session, client)` в memory.py:

1. Отрезает всё, кроме последних `KEEP_MESSAGES = 10` сообщений.
2. Отправляет отрезанное (плюс старое саммари, если было) той же модели с промптом `SUMMARY_PROMPT` → новое саммари.
3. При любой ошибке или пустом ответе — полный откат истории, диалог продолжается несжатым.
4. Из ответа reasoning-моделей вырезается `<think>...</think>`.

Саммари попадает в system-сообщение каждого следующего запроса («Краткое содержание предыдущей части диалога: ...»).

## RAG (rag.py)

- **Индексация** (`/rag add <путь>`): файл или папка рекурсивно (расширения из `TEXT_EXTS`), чанки по 800 символов с перекрытием 200, эмбеддинги батчами по 32 через LM Studio, всё в один JSON. Повторная индексация файла заменяет его старые чанки.
- **Эмбеддинг-модель** ищется автоматически: сначала `type == "embeddings"` в `/api/v0/models`, потом `"embed"` в id. Если не нашлась — подсказка скачать `nomic-embed-text`.
- **Поиск**: эмбеддинг вопроса → косинусная близость по всем чанкам (чистый Python) → топ-3 с score ≥ 0.45 → блок «Контекст из базы знаний» в отправляемой копии вопроса.
- **Состояние**: `rag_on` живёт в памяти процесса (после перезапуска — снова `/rag on`), индекс — на диске.

Линейный перебор осознанный: до нескольких тысяч чанков задержка незаметна. Если корпус вырастет — точка замены на numpy/FAISS одна: `RagIndex.search`.

## Профиль пользователя (user_profile.py)

Задача: обогащать системный промпт фактами о пользователе, **не замусоривая** его — «Мне 12 лет» уместно при «какие фильмы мне смотреть», но не при «сколько часов в сутках».

Испробованные и отвергнутые подходы (важно, чтобы не повторять):

1. **Эмбеддинг вопроса против эмбеддинга факта** — не работает: на коротких русских фактах nomic даёт «какие фильмы я могу смотреть?» ближе к «Я живу в Москве» (0.815), чем к возрасту (0.66); нерелевантные пары стабильно выше 0.7, порогом не разделить. Префиксы `search_query:`/`search_document:` не спасают.
2. **LLM-отбор перед каждым сообщением** — качество отличное, но qwen3.5-9b всегда «думает» (reasoning уходит в `reasoning_content`, `/no_think`, `enable_thinking: false` и `reasoning_effort` LM Studio игнорирует) и на оценочных вопросах сжигает 2000+ токенов за 10-20 с на каждое сообщение. Слишком медленно.

Рабочее решение — **триггеры**: при `/profile add` чат-модель один раз (~40 с, max_tokens 8000 из-за размышлений) генерирует ~12 примеров вопросов, при которых факт полезен. Вопрос пользователя сравнивается эмбеддингами с триггерами — сравнение «вопрос-к-вопросу» надёжно: «какие фильмы я могу смотреть?» даёт 0.94 с триггером возраста и ≤0.78 с остальными. Порог `MIN_SCORE = 0.85`, обе стороны с префиксом `search_query:`.

Детали:

- Дорогое LLM-рассуждение о релевантности происходит один раз при добавлении факта; на каждом сообщении — только один быстрый вызов эмбеддингов.
- Эмбеддинг текста самого факта тоже лежит в `vectors` (фолбэк). Факт без векторов (эмбеддинги были недоступны) подставляется всегда.
- Покрытие триггеров — лотерея: если автосписок упустил тему, `/profile hint <n> <вопрос>` дописывает триггер вручную, `/profile triggers <n>` показывает список.
- Режимы (`/profile mode`): `smart` — отбор по триггерам; `always` — все факты всегда; `off` — не подставлять. Если эмбеддинг-модели нет, `smart` деградирует до `always`.
- Факты подставляются в system-сообщение блоком «Факты о пользователе, относящиеся к его сообщению» и в историю не пишутся.

## Параметры генерации (gen_params.py)

Принцип «дефолта модели»: параметр, который пользователь не задавал, **не отправляется в запрос вообще** — тогда LM Studio применяет пресет самой модели. «Сбросить на дефолт» = удалить переопределение, а не подставить какое-то число. Не менять это на явные дефолты в коде.

- Переопределения хранятся по model id в `data/params.json`; при `/model` автоматически действует набор новой модели.
- `SPEC` — единственное место, где описаны параметры (тип, границы, описание); `/param` и валидация строятся по нему. Новый параметр = одна строка в `SPEC`.
- Стандартные OpenAI-параметры (`NATIVE`) идут аргументами SDK, специфичные для LM Studio (`top_k`, `min_p`, `repeat_penalty`) — через `extra_body`. LM Studio принимает все (проверено).
- `--temperature` из CLI действует только на текущий запуск (`persist=False`).
- Маленький `max_tokens` у reasoning-модели может дать пустой ответ (весь бюджет уходит в размышления) — chat.py печатает подсказку об этом.

## Дебаг-строка

После каждого ответа (отключается `/debug`): `[18.8 с | промпт 50 + ответ 2024 = 2074 ток. | 107 ток/с | контекст 25% из 8192]`. Данные из `usage` финального чанка стрима; у reasoning-моделей «ответ» включает невидимые токены размышлений. Без usage — оценка ~3 символа/токен и пометка «(оценка)».

## Подсказки команд (SlashCompleter)

Ввод пользователя читается через `prompt_toolkit.PromptSession` с `SlashCompleter` (chat.py): при наборе «/» показывается меню команд с описаниями, работают подкоманды и третий уровень (`/profile mode smart`, `/param <имя> default`). Источники данных меню — словари `COMMANDS` и `THIRD_LEVEL`; новая команда должна попасть и туда, и в `HELP_TEXT`, и в ветку `elif` в `main()`.

Если stdin — не терминал (пайп, тесты), prompt_toolkit не используется, ввод идёт через обычный `input()` с очисткой BOM. Иначе prompt_toolkit падает на отсутствии консоли Windows.

## Обработка ошибок и прерываний

| Ситуация | Поведение |
|---|---|
| Сервер не запущен при старте | Подсказка, выход с кодом 1 |
| Соединение упало / ошибка API во время генерации | Сообщение, вопрос откатывается, чат продолжается |
| Ctrl+C во время генерации | Прерывание; частичный ответ сохраняется, чат продолжается |
| Ctrl+C / Ctrl+D на приглашении «Вы:» | Штатный выход |
| Ошибка при саммаризации | Откат истории, чат продолжается несжатым |
| Ошибка эмбеддингов при поиске | Предупреждение, вопрос уходит без RAG-контекста |
| Старый LM Studio без `include_usage` | Повтор запроса без него; оценка токенов по символам |

## Как расширять

- **Новая команда чата**: ветка `elif cmd == "/..."` в `main()` + строка в `HELP_TEXT`.
- **Новый параметр генерации**: аргумент в argparse → `stream_reply` → `client.chat.completions.create`.
- **Другие форматы документов в RAG** (pdf, docx): извлечь текст в `RagIndex.add_path` перед `chunk_text`.
- **Другой OpenAI-совместимый бэкенд** (Ollama, llama.cpp): `--url`; сломается только расширенное `/api/v0` (есть фолбэк).
- **Настройки сжатия**: `COMPRESS_THRESHOLD` в chat.py, `KEEP_MESSAGES` и `SUMMARY_PROMPT` в memory.py.
- **Настройки профиля**: `MIN_SCORE`, `TRIGGER_PROMPT`, `MAX_TRIGGERS` в user_profile.py.

## Ограничения среды

- Windows / PowerShell 5.1: при пайпе в stdin попадает BOM (вырезается при чтении ввода), а кириллица требует `$OutputEncoding = UTF8` без BOM; в интерактивном терминале всё работает без настроек (PEP 528).
- Оценка токенов без usage грубая (~3 символа/токен для русского); реальный расход даёт только usage от LM Studio.
- `/load` сессии с другой моделью продолжает диалог текущей моделью (с предупреждением).
