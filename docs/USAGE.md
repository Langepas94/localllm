# Агент по трудовому праву — руководство пользователя

Приватный веб-сервис на VPS: локальная LLM (Ollama) отвечает на вопросы по Трудовому
кодексу РФ с опорой на RAG-поиск по тексту кодекса. Данные не покидают сервер.

Это тот же код, что и локальный `localllm` (CLI): веб-слой `web.py` использует тот же
`rag.py` и юр-режим `/legal`. Сервер собирается **ровно из git** — локально и на VPS
одна и та же программа.

**Адрес:** http://5.129.234.9/

---

## 1. Использование через сайт

1. Открыть **http://5.129.234.9/** в браузере.
2. В окне чата ввести вопрос по трудовому праву и отправить.
3. Ответ приходит кратко, со ссылкой на статью ТК РФ и списком статей-источников.

Первый запрос после простоя дольше (прогрев моделей). Обычный ответ — **~1–1,5 минуты**
(слабый CPU, без GPU).

## 2. Использование через API

```bash
# Вопрос
curl http://5.129.234.9/api/chat \
  -H "Content-Type: application/json" \
  -d '{"message": "За сколько предупредить об увольнении по собственному желанию?"}'
```
Ответ:
```json
{
  "answer": "По ст. 80 ТК РФ ... не позднее чем за две недели ...",
  "sources": [{"source": "tk-rf.pdf", "section": "Статья 80.", "quote": "..."}],
  "not_known": false
}
```
```bash
# Статус
curl http://5.129.234.9/api/health
# {"status":"ok","model":"qwen2.5:1.5b","embed_model":"bge-m3"}
```

- `not_known: true` — агент честно не нашёл ответа в кодексе (не выдумывает).
- Лимит вопроса — 1000 символов. Rate limit — 20 запросов/мин с одного IP (иначе `429`).

## 3. Примеры (проверено)

| Вопрос | Ответ | Статья |
|---|---|---|
| Срок предупреждения об увольнении по собственному | за две недели | ст. 80 |
| То же, на испытательном сроке | за три дня | ст. 71 |
| Продолжительность ежегодного отпуска | 28 календарных дней | ст. 115 |
| Максимальная рабочая неделя | 40 часов | ст. 91 |
| Обеденный перерыв | не более 2 ч и не менее 30 мин | ст. 108 |

Ключевая особенность: агент различает **общую норму и специальные случаи**. На общий
вопрос отвечает общей нормой (ст. 80, «две недели»), а если в вопросе есть особая
категория (испытательный срок, сезонные, срочный договор до 2 мес., руководитель,
спортсмен и т.п.) — нормой для этой категории.

## 4. Как это устроено

```
Браузер ──HTTP──► nginx :80 ──► web.py :8000 ──┬─► Ollama :11434  (qwen2.5:1.5b — ответ)
                                               └─► Ollama :11434  (bge-m3 — эмбеддинги)
                                                        ▲
                                         индекс ТК РФ (data/rag_index.json, 1416 чанков)
```

| Слой | Где на VPS |
|---|---|
| Сайт + API | `/opt/localllm-web` (systemd `localllm-web`, порт 8000) |
| Веб-сервер | nginx :80 → 127.0.0.1:8000 |
| LLM | Ollama :11434 — чат `qwen2.5:1.5b`, эмбеддинги `bge-m3` |
| Индекс ТК РФ | `/opt/localllm-web/data/rag_index.json` |

**Пайплайн ответа** (`web.py` → `rag.py`):
1. поиск по индексу (эмбеддинг вопроса `bge-m3` + косинус), 1 лучший чанк на статью;
2. фильтр по релевантности + LLM-переранжирование;
3. `special_case_reorder` — детерминированно поднимает общую норму над специальными
   (или норму нужной категории), по карте «статья → категории» (`build_category_map`);
4. контекст собирается из **лид-чанка** каждой статьи (заголовок + основная норма), топ-5;
5. генерация ответа `qwen2.5:1.5b` (temperature 0) строго по контексту;
6. если релевантного нет — детерминированное «Не знаю» без вызова модели.

## 5. Обновление сервиса (только через git!)

**Правило: на сервере руками ничего не менять.** Весь код — из git, деплой всё
перезаписывает из отслеживаемых файлов (гарантия «локально == на сервере»).

```powershell
cd C:\Users\Artempk\Documents\localllm
# ...правки в web.py / rag.py / chat.py / systemd / nginx...
git add -A ; git commit -m "..."
.\scripts\deploy.ps1        # выкатывает ровно git-состояние на VPS
```
Скрипт: пакует `git ls-files` → заливает → обновляет venv → (индекс собирает, только
если его нет) → ставит systemd+nginx из git → перезапускает → smoke-тест `/api/health`.

## 6. Обновление базы (индекс ТК РФ)

Индекс собирается **локально** (на VPS это часы — слабый CPU) и переносится файлом.
Нужен запущенный локальный Ollama с моделью `bge-m3` (`ollama pull bge-m3`).

```powershell
cd C:\Users\Artempk\Documents\localllm
# положить новые/обновлённые PDF или txt в corpus\
python scripts\build_index.py --url http://127.0.0.1:11434/v1 --embed-model bge-m3 --fresh
scp data\rag_index.json tg-agent-vps:/opt/localllm-web/data/rag_index.json
ssh tg-agent-vps "systemctl restart localllm-web"
```
⚠️ Модель эмбеддингов при сборке и в `systemd`-юните (`--embed-model`) должна совпадать,
иначе поиск сломается (векторы несовместимы).

## 7. Управление на сервере

```bash
ssh tg-agent-vps
systemctl status localllm-web      # состояние
systemctl restart localllm-web     # перезапуск
journalctl -u localllm-web -n 50   # логи
ollama ps                          # какие модели в памяти
free -m                            # память (обе модели живут через swap)
```

## 8. Настройка моделей

В `systemd/localllm-web.service`, строка `ExecStart`, флаги:
- `--model qwen2.5:1.5b` — чат-модель (ответ);
- `--embed-model bge-m3` — модель эмбеддингов (поиск).

Изменить → `git commit` → `scripts\deploy.ps1`. При смене `--embed-model` **пересобрать
индекс** той же моделью (см. п. 6). Модель должна быть в `ollama list` на VPS.

---

## 9. Ограничения

- **Demo-доступ:** HTTP по IP, без TLS и пароля — сервис открыт всем. Для боевого
  использования нужен HTTPS (домен + Let's Encrypt) и basic-auth.
- **Слабый VPS** (2 ядра, 1.9 ГБ RAM, без GPU): ответы ~1–1,5 мин; обе модели держатся
  в памяти через swap; параллельные запросы сериализуются (по одному за раз).
- **Небольшая модель** `qwen2.5:1.5b`: на нестандартных формулировках возможны менее
  точные или многословные ответы; при отсутствии нормы в кодексе честно отвечает «Не
  знаю». Это справочная информация, не индивидуальная юридическая консультация.
