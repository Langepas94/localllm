# Конфиг Ollama на VPS (важно для скорости)

Веб-сервис быстр (~30–40 с/ответ вместо ~90) только при правильной настройке Ollama
на сервере. Это инфраструктура сервера (не часть кода `localllm`), поэтому лежит вне
репозитория — но от неё напрямую зависит скорость. Файл на VPS:

`/etc/systemd/system/ollama.service.d/tuning.conf`

```ini
[Service]
# 4 ГБ RAM: держим эмбеддер (bge-m3, 1.2G) и чат (qwen2.5:3b, ~2G при ctx=2048)
# ОБА в памяти -> в запросе нет перезагрузки моделей (экономит ~30 с).
# ctx=2048 (наши промпты ~950 токенов) уменьшает KV-кэш -> обе модели влезают.
Environment="OLLAMA_KEEP_ALIVE=-1"
Environment="OLLAMA_MAX_LOADED_MODELS=2"
Environment="OLLAMA_NUM_PARALLEL=1"
Environment="OLLAMA_CONTEXT_LENGTH=2048"
```

Применить:
```bash
sudo systemctl daemon-reload && sudo systemctl restart ollama
```

Почему так:
- **Перезагрузка моделей — главный тормоз.** При `MAX_LOADED_MODELS=1` каждый запрос
  выгружал одну модель и грузил другую (embed↔chat) — ~30 с впустую. С `=2` обе резидентны.
- **`ctx=2048`** уменьшает KV-кэш, чтобы обе модели поместились в 4 ГБ (при 4096 не влезали —
  оставалось ~150 МБ, соединения рвались под нагрузкой).
- **Прогрев.** `web.py` при старте грузит обе модели (фоновый поток), чтобы первый запрос
  после рестарта не ждал холодную загрузку. Если делать запрос в первые ~40 с после
  деплоя/перезагрузки (пока идёт прогрев) — он может быть медленным или оборваться;
  подождите минуту после деплоя.

Требуются модели: `ollama pull qwen2.5:3b` и `ollama pull bge-m3`.

Потолок скорости — CPU (2 ядра, без GPU): 3b генерирует ~7 ток/с, обработка контекста
~22 ток/с. Быстрее (<20 с) — только GPU или меньшая модель.
